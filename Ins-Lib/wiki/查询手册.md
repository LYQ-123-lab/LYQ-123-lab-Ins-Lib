# 查询手册

> 对应 `../AGENTS.md` 支持指令第 2 条：「最近值得关注的方向 / 某个主题的发展变化 / 可组合的选题」
> 本库要能回答的五类问题，各自有固定的查法。**不要每次临时想怎么查。**
> 本机没有 `rg`，一律用 `grep`（在 Ins-Lib 根目录下执行）。

---

## Q1 · 最近什么值得关注？

1. 读 [[index]] 的状态表，看最近一次抓取的时间和条目数
2. 读 `trends/` 下所有页，按「更新」日期排序——最近被反复更新的趋势页就是活跃方向
3. 扫 [[log]] 最近 3 条 `ingest`，看 Agent 当时判定了什么

输出格式：**3 条以内**。列太多等于没列。每条说清「是什么 + 为什么现在值得看 + 证据几条」。

## Q2 · 某个主题发生了什么变化？

```bash
grep -ril "主题关键词" wiki/          # 找相关页面
grep -rn "主题关键词" wiki/*.md wiki/*/*.md   # 看上下文
```

然后**按时间读**：从最早的记录读到最新，把变化写成一条时间线。

重点回答三件事：最初是什么判断 → 后来被什么修正 → 现在的结论是什么。
如果中间出现过矛盾（见 [[价值分层]] 第三刀），一定要说出来，那是认知真正更新的地方。

## Q3 · 有哪些反复出现的信号？

信号 = **≥3 次、跨 ≥2 个源站、跨 ≥3 天**（认定标准见 [[价值分层]]）。

```bash
grep -ric "关键词" raw/               # 在原始层统计出现次数，比 wiki 更全
grep -rl "关键词" raw/                # 看分布在哪些批次
```

查原始层而不是 wiki 层——wiki 已经过滤过一轮，会低估出现频次。
统计结果要带**具体条数和日期**，不给数字的"最近很火"不算结论。

## Q4 · 哪些信息可以组合成新的选题？

1. 打开 [[选题池]]，看现有条目
2. 找**跨类的连接**：一条政策（A 类源）+ 一个公众争论（D 类源）+ 一个具体案例（E 类源）= 一个选题
3. 单类信息内部拼不出好选题，**跨类组合才是本库的独有价值**

组合规则与准入门槛见 [[选题池]]。

## Q5 · 我过去围绕某个方向积累过哪些素材？

```bash
grep -ril "方向关键词" wiki/ raw/
```

分两组汇报：
- **已提炼的**：wiki 页里的判断、观点、趋势
- **未提炼的**：raw 里躺着但从没被引用的条目 —— 这些是被遗忘的素材，往往最值得翻出来

第二组特别重要。它回答的是「我攒了什么但自己忘了」。

---

## 通用约定

- 每个回答都要**能追溯**：结论后面跟来源（raw 批次 + 源站 + 日期）。
- 分不清事实与推测时，推测必须标 `[推测]`。
- 查不到就直说查不到，不用相近内容凑数。
