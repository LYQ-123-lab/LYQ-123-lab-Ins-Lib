# 每日入库流程

> 每次抓取入库照这 8 步走。**简单、固定、可重复** —— 流程不固定，知识库就会随每次执行者的心情漂移。
> 对应 `../AGENTS.md` 支持指令第 1 条：「读取 RSS 订阅源，获取自上次执行以来的新内容，按规则入库更新 wiki」

## 边界（每次开工先确认）

- 本库根目录：`C:\Users\41339\Desktop\LLM-Workbench\Ins-Lib\`
- **只读写本目录内的文件。** 严禁跨到 `../Vibe-Note/`、`../Style-Lib/` 或任何其他库。
- 所有 wikilink 只在 Ins-Lib 内部相对引用（`[[topics/xxx]]`），不链出本库。

## 步骤

### 1. 确定抓取窗口

读 [[index]] 状态表的「上次抓取时间」，从那个时间点抓到现在。没有记录就抓最近 24 小时。

### 2. 拉源

**33 个源全部拉取，不做取舍、不设低频**（`../AGENTS.md` 订阅规则 10）。每次只取**自上次抓取以来的新增条目**。

上一批的抓取时间从 [[index]] 状态表「上次抓取时间」取，没有记录就取最近 24 小时。

### 3. 存 raw

抓到的内容写进 `raw/YYYY-MM-DD-批次NN.md`，同一天第二次抓取就 `批次02`。

每条必须完整保留：**标题原文 · 源站 · 发布时间 · 原文链接 · 原文全文**。

- **全文优先**：能抓到全文就存全文，这是订阅规则 2 的硬要求。抓不到全文才退而存摘要，且必须在该条目上标注 `（仅摘要）` —— 不标注就会让后人误以为这是完整信息。
- 链接是这条内容的唯一身份，必须完整照抄，不缩短不改写。
- **链接写成 `[原文链接](<https://xxx>)`**（订阅规则 11）。URL 必须套尖括号，禁止裸写 —— 裸 URL 在 Obsidian 里点不动，带下划线或参数的链接尤其容易断。
- 英文源（I 类）标题保留英文原样，不译。
- 格式见 `../raw/README.md`。

### 4. 去重 ← 先查再处理

**处理任何一条之前**，先到 [[处理台账]] 里查这条链接：

```
grep -F "链接" wiki/处理台账.md
```

- 查到 → 跳过，不重复分析
- 没查到 → 继续第 5 步

> 本机没有 `rg`，一律用 `grep`。

### 5. 定性 + 打标

对每条新内容：

1. 先看是否命中 [[价值分层]] 的**七个提炼方向**（媒介现象 / 平台算法 / 短视频账号案例 / AIGC 生产 / 舆论演变 / 媒体融合 / 国际传播）——一项都没命中的，多半是【短时新闻】
2. 走 [[价值分层]] 三刀：什么类型 → 价值高不高 → 和过去什么关系
3. **打三类标签**：
   - 类型标签（五选一）：【短时新闻】/【持续趋势】/【核心观点】/【优质案例】/【创作选题】
   - 主题标签（六个固定，选 1–3 个）：#媒体融合 #AIGC传播 #平台研究 #舆论观察 #新媒体案例 #国际传播
   - **分组标签（二选一，由源站决定）**：`#A新传主线` / `#B宏观补充`

低价值的到此为止，台账记 `跳过`，流程结束。

### 6. 搜旧页，决定更新还是新建

**先搜，再决定。** 建页前必须 grep：

```
grep -ril "关键词" wiki/
```

- 命中 → **更新既有页**，绝不新建第二个家
- 未命中 → 才建新页

默认动作永远是「更新已有认知」，新建页面是例外。这条不遵守，库就会退化成每天一堆孤立摘要。

**关联时同组优先**（见 [[价值分层]]「关联规则」）：先在同组的既有页面里找连接点；跨组关联只在确有内在逻辑时才建，且必须在链接处写明理由。宁可暂时少一条链接，也不为了消除孤立而硬凑。

### 7. 写 wiki

新页或更新页都要带这些字段：

```markdown
---
类型: 【短时新闻】|【持续趋势】|【核心观点】|【优质案例】|【创作选题】
标签: #媒体融合 #AIGC传播 #平台研究 #舆论观察 #新媒体案例 #国际传播（选 1–3 个）
分组: #A新传主线 | #B宏观补充（由源站决定，二选一）
创建: YYYY-MM-DD
更新: YYYY-MM-DD
证据条数: N
相关源站: 源站A、源站B
---
```

正文里每条结论后面必须跟溯源：

```
（来源：[[../raw/2026-10-27-批次01]] · 央视新闻联播 · 2026-10-27）
```

引到具体条目时附原文外链，URL 套尖括号：

```
（来源：[[../raw/2026-10-27-批次01]] · 量子位 · 2026-10-27 · [原文链接](<https://xxx>)）
```

然后补**双向链接**：新页链出去，被提到的旧页回来补反链。单链是半成品。

**两种链接别混用**（订阅规则 11）：库外原文用 `[原文链接](<url>)`；库内页面之间一律用 `[[笔记名]]`。库内改用 Markdown 链接会让 Obsidian 反链和关系图失效。

### 8. 收尾（缺一项就是没做完）

1. 把本次处理过的链接追加进 [[处理台账]]
2. **更新失败计数**（回 [[源站清单]] 改状态栏）：
   - 本次成功 → 清零，删掉 `[连续失败 N 次]` 标注
   - 本次失败 → 次数 +1
   - **有任一源累计 ≥7 次 → 必须在给你的汇报里单独列出，请用户决策**（换实例 / 换自有 feed / 改手动投喂 / 移除）。在此之前不擅自动它
3. 更新 [[index]]：状态表（上次抓取时间、条目数、页面数）+ 新页入目录
4. 在 [[log]] 追加一条 `ingest`，写清：抓了哪些源、多少条、新建/更新了哪些页、跳过多少、失败源各累计几次
5. 如有值得开写的题目，加进 [[选题池]]

## 硬性约束

- **raw 只增不改。** 原文什么样存什么样，不润色不修正。
- **不虚构。** 抓不到就说抓不到，源站失效就标失效，不编造条目充数。
- **不建孤立摘要页。** 一个页面至少要有一条出链，且至少被另一页引用。
- **失效源不擅自处置。** 抓取失败照实记录、累加计数，连续失败 ≥7 次才上报用户决策。不自行替换路由、不自行删除源站。
- **不引入任何数据库、向量库、外部基础设施。** 只有文件夹、Markdown 和 Agent。
- **含反引号的内容不经过 shell 写入。** 用文件写入工具直接落盘，不要用 `python -c "..."`、heredoc 这类命令行内联文本 —— shell 会先解释反引号，把 `` `[待用户决策]` ``、`` `[待核]` `` 变成空字符串；表格里多出来的 `|` 还会把一列拆成两列。写完必须复验：**表格行是否以 `|` 结尾、反引号是否成对、有无内容被掏空的断句**。

## 完成标准

一次合格的入库，能用一句话说清：**「今天进来的 N 条里，有 X 条更新了已有认知，Y 条长出了新主题，Z 条被判定为噪音跳过。」**

说不出这句话，就是没做完。
