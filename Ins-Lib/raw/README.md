# raw — RSS 原始层

> **只增不改。** 这里是 Ins-Lib 的唯一事实来源，wiki 里每一条结论都必须能追回这里的某一篇原文。

## 放什么

- Agent 按 `../AGENTS.md` 的订阅源抓取回来的**原始条目**：标题、来源链接、发布时间、**原文全文**（订阅规则 2 的硬要求）。
- 你自己手动丢进来的文章、截图转文字、网页存档，也放这里。

## 不放什么

- 整理后的判断、趋势归纳、选题想法 —— 那些属于 `wiki/`。
- 任何加工过的版本 —— 原文什么样就存什么样，错别字、通稿腔、不完整的摘要都保留，不要"顺手修一下"。

## 文件组织

按**抓取批次**存，一个批次一个文件：

```
raw/2026-10-27-批次01.md
raw/2026-10-27-批次02.md
raw/2026-11-03-批次01.md
```

同一天多次抓取就递增批次号。手动投喂的文件用 `raw/YYYY-MM-DD-<标题>.md`。

## 条目格式（必须遵守）

一个批次文件内按源站分节，每条一个三级标题：

```markdown
## 央视新闻联播

### 新闻标题原文照抄（英文标题不译）
- 源站：央视新闻联播
- 链接：[原文链接](<https://...>)
- 发布时间：2026-10-27 09:00
- 全文：
  > 原文正文完整录入……

### 下一条标题
- 源站：
- 链接：[原文链接](<https://...>)
- 发布时间：
- 全文：
```

**全文优先，摘要是退路。** 能抓到全文就存全文（订阅规则 2）；抓不到才存摘要，且必须在该条目标 `（仅摘要）`——不标注，日后无从判断这条信息是完整的还是残缺的。

**链接是这条内容的唯一身份。** 去重、溯源、判断是否处理过，全靠它 —— 所以链接必须完整照抄，不要缩短、不要改写、不要省略参数。

**链接必须写成可点击的 Markdown 链接**（`../AGENTS.md` 订阅规则 11）：

```
[原文链接](<https://xxx>)
```

两条硬要求：

1. **URL 外套尖括号** `<>`。RSS 链接里常见的下划线（`_id=123`）、`&`、`?` 在 Markdown 里会被当成强调符号或破坏解析，套上尖括号才能原样传递、在 Obsidian 里点击即跳转。
2. **禁止裸写 URL。** 裸 URL 在 Obsidian 里常常不可点击，短链、带参数的链接尤其容易断。

> 历史批次（`2026-10-27-批次01/02`）里的链接是裸写的，按用户决定**不批量回改**。从下一个批次起全部用新格式。

## 去重

抓到内容后，**先查 `../wiki/处理台账.md`** 里有没有同一条链接：

- 有 → 跳过，不重复入库，不重复分析。
- 没有 → 入库分析，分析完把链接追加进台账。

台账里没有的就是没处理过的。这条规则没有例外。

## 溯源格式

wiki 页面引用原文时统一写成：

```
（来源：[[../raw/2026-10-27-批次01]] · 央视新闻联播 · 2026-10-27）
```

细到具体条目时，附上原文外链，同样用尖括号包 URL：

```
（来源：[[../raw/2026-10-27-批次01]] · 量子位 · 2026-10-27 · [原文链接](<https://xxx>)）
```

读者能从 wiki 一句话直接跳回原始条目，这条链路断了就是不合格的页面。

## 两种链接的分工

| 指向 | 语法 | 说明 |
|---|---|---|
| 库外网页（原文） | `[原文链接](<https://xxx>)` | 标准 Markdown，尖括号包 URL |
| 库内页面（笔记） | `[[topics/笔记名]]` | Obsidian 原生双链，不改 |

**不要混用**：库内页面之间不要用 Markdown 链接指向 `.md` 文件——那样 Obsidian 的反向链接和关系图就失效了，而那正是这套库的核心价值。
